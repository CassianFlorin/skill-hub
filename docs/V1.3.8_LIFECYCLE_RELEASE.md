# V1.3.8 Lifecycle Release

## Goal

`v1.3.8` packages the lifecycle-management work that makes Skill updates safer for day-to-day agent use. It focuses on update awareness, update preview, update holds, rollback history, targeted rollback, and immediate runtime redeploy after rollback.

## User problems addressed

- Users can see when installed Skills have newer source versions before changing files.
- Users can preview an update and see source, targets, deployed runtimes, and rollback guidance before writing.
- Users can freeze known-good Skill versions with a reason so broad updates skip them.
- Users can list rollback snapshots and choose a specific historical version instead of only the latest previous copy.
- Users can rollback and redeploy the restored copy to a runtime in one command, including a Hermes profile.

## New and updated commands

```bash
skillhub check
skillhub update --preview
skillhub update --dry-run
skillhub hold <identity> --reason "known-good version"
skillhub holds
skillhub unhold <identity>
skillhub update [identity]
skillhub history <identity>
skillhub rollback <identity> --to <version>
skillhub rollback <identity> --to <version> --deploy hermes --profile work
```

## Release validation

Before tagging `v1.3.8`, verify from the release branch:

```bash
go test ./...
npm test --prefix npm
go build ./cmd/skillhub
npm pack --prefix npm --pack-destination /tmp
```

Recommended lifecycle smoke:

1. Install a local-registry Skill at `1.1.0`.
2. Update the source to `1.2.0`, then `1.3.0`.
3. Run `skillhub history <identity>` and confirm both snapshots are listed.
4. Run `skillhub rollback <identity> --to 1.1.0 --deploy hermes --profile work`.
5. Confirm both the managed store copy and Hermes profile runtime copy contain the `1.1.0` contents.

## Tagging

```bash
NEXT_TAG=v1.3.8
git tag -a "${NEXT_TAG}" -m "${NEXT_TAG}"
git push origin "${NEXT_TAG}"
```

The release workflow injects `${NEXT_TAG}` into the Go binary via `-ldflags`, sets the npm package version from the tag during release, builds platform archives, creates checksums, publishes the GitHub Release, and publishes npm/Homebrew installers when secrets are configured.
